# contracts/actions/v1

The JSON one headless action verb prints on stdout. Eight verbs are in scope:
`pull`, `open-pr`, `propose-pr`, `pr-detail`, `merge`, `post-merge-sync`,
`issue-lookup`, `issue-create`. `snapshot` has its own shape and belongs to
`snapshot/v1`; the interactive TUI prints no envelope at all.

Consumers **vendor a pinned copy** of `actions.schema.json` inward. Nothing
reads this directory across a repo boundary at run time.

## The three-state rule

This is the whole point of the contract, and the failure it exists to prevent:

| on the wire | meaning |
|---|---|
| field **absent** | this verb has no such concept |
| field present, **`null`** | applicable, value **unknown** |
| field present, **`false`** | applicable, definitely negative |

Collapsing "absent" with "null" is what makes `pull.matches` and
`issue-lookup.matches` look alike — one means "no inbox here", the other
means "the inbox was not read exhaustively". A consumer that treats them the
same files a duplicate into an inbox it never read.

The three places where `null` is load-bearing:

- `issue-lookup.matches` / `.malformed` — `[]` was read and is empty; `null`
  was not read to the end (the list cap was hit, or a candidate could not be
  mapped).
- `issue-create.created` — `true` created; `false` definitely not created on
  this attempt; `null` the mutating call broke and **may have landed**. Look
  again; never create again.
- `merge.merged` — `true` merged; `false` only reachable *before*
  `gh pr merge` is launched; `null` the call was launched and its outcome
  could not be established. Never retry a merge on `null`.

## Envelope variants

`result_kind` selects the variant. Only `action` means a verb answered and
its own required fields apply.

- **`action`** — one of the eight verbs. `action` selects the leaf.
- **`cli_error`** — argv was refused before dispatch; **nothing ran**.
  `action` is *diagnostic only*: it may name the attempted verb, an unknown
  string, or `"unknown"`, and never selects an action payload.
- **`contract_error`** — the producer detected its own wire drift and refused
  rather than ship a payload contradicting this schema. **Not a ninth verb.**
  Treat it as a producer bug and fail closed.

A consumer that meets an unknown `result_kind` or an unknown
`schema_version` must **fail closed** — not fall back to best-effort parsing.
An envelope it cannot interpret is not an empty result.

## Exit codes are contract, not decoration

`0` when `ok` is true, `1` when it is false, and the two must **agree**. A
consumer that parses the JSON and ignores the code would accept a producer
that answers correctly and exits wrongly; the test runner here refuses that
combination, and proves it can by driving itself with a deliberately wrong
expectation.

`--help` is not a verb invocation: it exits `0`, prints usage, and is outside
this contract.

## Evolution

**Additive within v1** (no version bump, consumers keep working):

- a new **optional** field on an existing verb, defaulting to `null`;
- a new value in an open-ended string field that is not an `enum` here;
- a new verb, provided it gets its own leaf and existing leaves are untouched;
- wording changes to `error` / `detail`, which are human-facing and must
  never be parsed.

**Breaking, requires v2** (a new directory, a new `schema_version`):

- removing a field, or making an optional one required;
- narrowing a type, including `nullable` → non-nullable — that is exactly how
  "unknown" gets destroyed;
- adding or removing a member of a closed `enum` (`local_sync`, `pr_state`,
  `issue_ref.state`);
- changing what an existing value *means*, even with the same type. Turning
  `merged: false` from "definitely not merged" into "merge failed, state
  unknown" is a breaking change with an unchanged schema, and the only
  protection is that it is written down here.

A consumer must ignore fields it does not know within its major version, and
must refuse a major version it does not know.

## Files

- `actions.schema.json` — JSON Schema draft 2020-12, `oneOf` over
  `result_kind`, then `oneOf` over the eight verbs.
  `additionalProperties: false` on every leaf.
- `fixtures/` — static golden payloads, one per distinguishable outcome
  family. They are **not** regenerated by the test suite: a golden the tests
  rewrite records whatever the code currently does, which is the opposite of
  a contract. When the producer changes deliberately, the fixture is updated
  by hand in the same commit.

## What is *not* contract

`error` and `detail` are human-facing. `local.error` in particular carries
git's own wording, which varies by version, locale and platform: the fixture
records one real example, but only its **presence and non-emptiness** are
pinned. Parsing either field is a consumer bug.

## What the tests guarantee

`tests/test_contract_v1.py` holds the schema and the binary to each other:

- every fixture validates;
- the fixtures cover all eight verbs and both error variants;
- each schema leaf's key set equals the emitter's — otherwise the schema and
  the producer become two sources of truth free to drift, and the schema
  would keep validating fixtures it generated while the binary shipped
  something else;
- the **real** binary's output validates, not only the fixtures. That path
  has already earned its place: it caught a `cli_error` shipping without
  `schema_version`, which a model-level check passed because the field has a
  default and `exclude_unset` dropped it from the wire.
