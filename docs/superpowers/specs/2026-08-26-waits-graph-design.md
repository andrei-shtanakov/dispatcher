# Waits graph — граф ожиданий флота в панели (дизайн)

Статус: draft · Дата: 2026-08-26 · Репо: dispatcher
Принятие inbox #201 (`slug: waits-graph-view`, запрос ecosystem-kb).

## 1. Контекст и цель

Панель dispatcher показывает состояние по эпикам, но **ось ожиданий** — рёбра
`@blocked_by` и сторожевые `@trigger` между репо — не рендерится нигде во
флоте: она существует как теги в TODO.md, находки сенсора и проза дайджеста
robin. Цена невидимости измерена в день запроса: ожидание
`deployer/pilot-dag-drop-branch-precondition` простояло открытым двое суток
после закрытия своего блокера maestro#216, потому что тег был в переходной
форме и канал молчал; нашёл его только разовый ручной снимок.

Замер 2026-08-26 (греп по 20 репо): 19 рёбер `@blocked_by` (13 канонических
`todo://`, 6 переходных `<repo>#N`), ~60 пунктов с `@trigger:"…"`, три
узла-концентратора.

Цель: постоянная поверхность в web-панели, отвечающая на три вопроса —
кто кого ждёт; какие ожидания уже доставлены (действуй); какие ссылки
не образуют рёбер и почему.

## 2. Не-цели

- **Пересчёт семантики plan-fields.** Рёбра, резолюция ссылок, вердикт
  «блокер доставлен» — целиком канонический пакет `plan_fields`
  (`packages/plan-fields`, вендорится этим же репо); view только раскладывает
  готовый снапшот. Ни одного собственного регекса по тегам.
- **Мультимашинность.** Slice 0 читает живые чекауты этой машины. Источник
  «published snapshot из KB» — отдельное расширение, отдельным решением
  (данные per-host уже едут в `derived/snapshots/`, но канал достраивается —
  см. #199); дизайн не должен ему мешать, но и не обязан его нести.
- **Граф @trigger-условий.** Условие триггера — свободный текст; ребра из
  него не существует. Триггеры показываются списком-слоем, не узлами графа.
- **Новая JS-библиотека.** 19 рёбер не оправдывают зависимость; рендер —
  собственный небольшой SVG/JS в существующей статике. При росте графа
  порог пересмотра назван в §6.
- **Мутации.** View строго read-only; никаких «закрыть пункт из панели».

## 3. Архитектура

Новый модуль `dispatcher/core/waits.py` + роут `GET /api/waits` +
секция «Waits» в `dispatcher/server/static/index.html`. Шаблон — тройка
эпиков (`core/epics.py` → `/api/epics` → секция Epics): те же паттерны
чтения флота, та же дисциплина честности.

### 3.1 Источник данных

Скелет — как `_todo_plane` в `core/epics.py:177`: `manifest_index(manifest)`
→ `checkout_map(workspace_root, index)` → `parse_fleet(inputs, index)`,
поверх снапшота — `check_fleet(doc)` (даёт `PF-BLOCKER-STALE`). Одно
отличие от прецедента, и оно нормативно: **inputs несут ВСЕ репо манифеста**,
не только чекауты с TODO.md — `RepoInput(name, todo_text)` для прочитанного,
`RepoInput(name, None, available=True)` для чекаута без TODO.md,
`RepoInput(name, None, available=False)` для отсутствующего чекаута. Только
так `parse_fleet` различает `PF-BLOCKER-NO-TODO` и
`PF-BLOCKER-UNRESOLVABLE`; пропуск репо из inputs (как в `_todo_plane`)
схлопнул бы оба случая во второй.

Состояния источника (модель PlaneState из epics, с её же семантикой
`read | partial | unavailable`):

- манифест не найден, ЛИБО манифест/workspace не читается — любой сбой
  `manifest_index`/`checkout_map` (UnicodeDecodeError, TOMLDecodeError,
  неоднозначный `git_dir`, OSError обхода) — → `state="unavailable"`,
  detail = класс ошибки; view отдаётся всегда, HTTP 200 — недоступность
  это содержимое, не ошибка транспорта;
- ни одного TODO.md → `unavailable` с иным detail;
- часть репо без чекаута/без TODO.md/с нечитаемым TODO.md →
  `state="partial"` (по прецеденту epics: `read` значит «прочитано всё»),
  и список `absent_repos` в ответе всегда присутствует (пустой = все
  прочитаны): ссылка В отсутствующий репо не резолвится, и читатель должен
  видеть, что дыра — от среды, а не от автора ссылки. `parse_fleet` уже
  отдаёт это диагностиками (`PF-BLOCKER-REPO-UNKNOWN` для незадекларированного
  репо, `PF-BLOCKER-NO-TODO` / `PF-BLOCKER-UNRESOLVABLE` для environmental);
  view их не глотает.

Чтение TODO-файлов — в новом модуле, per-file `try/except`
(UnicodeDecodeError/OSError → репо в `absent_repos` с причиной
`unreadable: <класс>`, проход живёт). Это НОВОЕ поведение waits.py:
прецедент `_todo_plane` читает файлы без стража, и его чинить эта работа
не обязана (не-цель: чужая секция). Отображение нечитаемого файла в
`RepoInput`: `RepoInput(name, None, available=True)` — то есть для пакета
он неотличим от «чекаут есть, TODO нет» (`PF-BLOCKER-NO-TODO`), и это
принятая аппроксимация: у сигнатуры пакета нет третьего состояния, а
вводить его — правка канона, не этого view. Правду о причине несёт
`absent_repos` этого же ответа (`unreadable: …` против `no TODO.md`);
входящие ссылки в оба случая честно говорят «цель не прочитана».

Вызов на каждый GET, без кэша — как у `/api/epics` (прецедент: тот тоже
парсит флот на запрос; при 21 репо это десятки миллисекунд, а кэш добавил
бы вопрос инвалидации, которого сейчас нет).

### 3.2 Форма ответа `/api/waits` (pydantic, как EpicsView)

```
WaitsView:
  todo_plane: {state: read|partial|unavailable, detail?: str, repos_read: int}
  absent_repos: [{repo, reason}]     # чекаут/TODO.md отсутствует/не читается
  edges: [WaitEdge]                  # только настоящие рёбра
  loose_refs: [LooseRef]             # ссылки, не ставшие рёбрами
  findings: [Finding]                # blocker-диагностики пакета, дословно
  triggers: [TriggerItem]            # сторожевой слой
  generated_at: str                  # wall-clock запроса, ISO
WaitEdge:
  source: NodeRef                    # {node_id, repo, title, status}
  target: NodeRef
  state: "waiting" | "stale"        # stale = PF-BLOCKER-STALE:
                                     # цель закрыта, источник открыт
LooseRef:
  source_node_id: str
  repo: str                          # репо источника (из провенанса ссылки)
  raw_ref: str                       # как написал автор
  normalized: str | null             # legacy_blocker_ref, если есть
Finding:
  code: str                          # PF-код, как выдал пакет
  subject_uri: str | null
  related_uri: str | null
  message: str                       # текст пакета дословно
  repo: str                          # из провенанса диагностики
TriggerItem:
  node: NodeRef
  condition: str                     # текст @trigger
```

Правила раскладки снапшота. **Ключевое решение: loose_refs и findings НЕ
сшиваются.** У диагностик пакета нет машинного ключа к конкретной ссылке
(`PF-LEGACY-AMBIGUOUS` несёт `related_uri=None`, а два legacy-тега одного
узла неразличимы по subject/provenance) — сопоставление потребовало бы
разбирать `message`, то есть пересчитывать семантику пакета, что запрещено
не-целями. Поэтому view показывает оба списка как есть: ссылки — по полям
самих references, причины — отдельной таблицей диагностик дословно.

- `edges` — из `doc["edges"]` (kind `blocked_by`); `state="stale"` для рёбер,
  на которые указывает `PF-BLOCKER-STALE` из `check_fleet` (матч по паре
  subject_uri/related_uri = source/target node_id — у ЭТОГО кода оба поля
  заполнены, матч машинный). **Stale-ребро остаётся в `edges`** — это
  состояние ребра, не его исчезновение: исчезнувшее «доставлено» читается
  как «ожидания нет», и это ровно тот дефект, который поверхность должна
  лечить.
- `loose_refs` — references с `resolved_target == null`, все поля — из
  самой ссылки (source_node_id, raw_ref, legacy_blocker_ref); никакого
  reason-поля у ссылки нет. Legacy-ссылка с единственным матчем тоже
  здесь — она видна как «текст, не ребро» самим фактом присутствия в
  этом списке (пакет для неё осознанно молчит, и view это молчание
  не подменяет собственным кодом).
- `findings` — диагностики `parse_fleet` + `check_fleet` семейства ожиданий
  (`PF-BLOCKER-*`, `PF-ID-DANGLING`, `PF-LEGACY-*`), кроме
  `PF-BLOCKER-STALE` (тот уже показан состоянием ребра). Поля — дословно
  из диагностики; `subject_uri` может быть null, и Finding это допускает.
- `triggers` — открытые не-tombstone узлы с непустым `trigger`.
- Сортировка всех списков детерминированная: edges по
  (target.node_id, source.node_id), loose_refs по (source_node_id, raw_ref),
  findings — порядком `canonicalize` пакета, triggers по node_id.
  Детерминизм заявляется по этим спискам; `generated_at` — wall-clock
  запроса и в сравнение не входит (тест сравнивает ответы без него).

### 3.3 Рендер (секция «Waits» в index.html)

Собственный SVG, без библиотек. Раскладка — **двухколоночная**: слева
источники (кто ждёт), справа цели (кого ждут), сгруппированные по репо;
ребро — кубическая кривая между колонками. Это сознательно НЕ force-layout:
у ожиданий есть естественное направление «потребитель → продюсер», и
колонки его показывают; сила ничего не добавляет при 19 рёбрах.

- Узел: прямоугольник с `repo/@id`, титул тултипом; цель с ≥2 входящими
  рёбрами помечается счётчиком (концентратор).
- Ребро `waiting` — сплошная линия нейтрального цвета; `stale` —
  акцентный цвет + бейдж «доставлено» у источника. Легенда обязательна.
- `loose_refs` — таблицей ПОД графом, не в графе (они не рёбра, и рисовать
  их линиями значило бы врать формой): source, raw_ref, normalized.
  Под ней — таблица `findings` (код + message дословно): читатель сам
  видит, какая причина к какой ссылке относится, по repo/URI в message —
  это его глаза, а не наш парсер.
- `triggers` — сворачиваемый список по репо, как остальные секции панели.
- `absent_repos` и `todo_plane.state != "read"` — строка-дисклеймер над
  графом (та же дисциплина, что `partial`-строки Epics).
- Данные грузятся из `refresh()` **отдельным вызовом с собственным catch,
  вне основного `Promise.all`** — ровно как секция Epics
  (`index.html:711-725`): отказ `/api/waits` красит только свою секцию и
  не гасит остальные панели. Пустой граф (0 рёбер) рисует секцию с явным
  «рёбер нет», не прячет её.

## 4. Ошибки и деградация

- `parse_fleet`/`check_fleet` бросили (дефект пакета/входа) →
  `todo_plane.state="unavailable"`, detail = класс ошибки, HTTP 200,
  пустые списки. Панель живёт, секция честно говорит «не прочёл».
- Нечитаемые манифест/workspace и per-file TODO — определены в §3.1
  (unavailable и absent_repos соответственно).
- Пункт с двумя `@blocked_by` — штатен: два ребра от одного источника.

## 5. Тесты

Паттерн — тесты epics view (`tests/test_epics_view.py`): фикстурный
воркспейс из tmp-манифеста + TODO-файлов, никаких моков пакета.

- каноническая ссылка на существующий @id → ребро `waiting`;
- цель закрыта `[x]` → ребро остаётся, `state="stale"` (регрессионный:
  stale не исчезает из edges), и `PF-BLOCKER-STALE` НЕ дублируется в
  findings;
- legacy `<repo>#slug` с единственным матчем → НЕ ребро; в `loose_refs`
  с normalized, findings по нему пусты (осознанное молчание пакета);
- legacy без матча / с двумя → loose_refs + `PF-LEGACY-AMBIGUOUS` в
  findings;
- `todo://` в отсутствующий @id → loose_refs + `PF-ID-DANGLING` в findings;
- ссылка в репо без чекаута → loose_refs + PF-BLOCKER-UNRESOLVABLE в
  findings + репо в absent_repos, `state="partial"`;
- нечитаемый TODO.md одного репо (битая кодировка) → absent_repos с
  причиной, `partial`, проход жив;
- манифест отсутствует ИЛИ не парсится → unavailable, HTTP 200, пустые
  списки (оба случая);
- триггеры: открытый пункт с @trigger попадает, закрытый — нет;
- детерминизм: два вызова по одной фикстуре → идентичные ответы без учёта
  `generated_at`;
- пункт с двумя @blocked_by → два ребра.

UI-слой: smoke-тест наличия секции и данных (как для остальных секций
статики, если такой паттерн есть; отрендеренные слова легенды и
дисклеймеров проверяются глазами при приёмке — см. §7).

## 6. Пороги пересмотра

- Рёбер > ~60 или узлов > ~120 → двухколоночная раскладка перестаёт
  читаться; тогда решение о библиотеке/иерархической укладке, отдельным
  пунктом.
- Появился канал published-снапшотов (#199 закрыт и robin-срез 2 поехал) →
  пункт «waits по снапшотам per host» заводится тогда, не сейчас.

## 7. Приёмка

- `/api/waits` на живом воркспейсе владельца согласуется с замером 26.08
  (минус погашенное к тому моменту): канонические `todo://`-ожидания (13 в
  замере) — в `edges`, переходные формы (6 в замере, включая
  dispatcher#199-ссылки robin и волта) — в `loose_refs`, НЕ в edges;
  stale-ребро показано, если есть в природе.
- Глазами: у stale-ребра бейдж и легенда читаются; loose_refs отделены от
  графа; секция при пустом графе не исчезает.
- CI dispatcher зелёный (pytest + ruff + pyrefly + codex-гейт по
  экономичному циклу).
